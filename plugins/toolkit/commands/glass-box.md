# Glass Box

On-demand provenance audit of your last answer, or of the answer you are about to give.
The deep, explicit version of the `claim-provenance` doctrine's irreversible-go-ahead
tell. Invoke it when an answer feels too confident, an action is hard to undo, or you
want the assumption surfaced before you act.

## Usage

$ARGUMENTS

Arguments, if any, name the answer or decision to audit. With no arguments, audit the
most recent substantive answer in this session.

## What to do

Do not narrate your thinking. A polished account of how you reasoned is not evidence,
and a convincing one can launder a wrong answer into a trusted one. Instead surface what
can actually be checked:

1. **The load-bearing fact.** The single fact this answer rests on — the one that, if
   wrong, flips it. Tag it verified (you ran it, read it, observed it) or derived
   (reasoned from docs, memory, structured output, an unexamined source).
2. **The unchecked assumption.** State plainly what you did not check but the answer
   depends on. Name the specific place you did not look.
3. **The offer.** If that fact is only derived, offer to verify it now — the concrete
   check, not a promise. If verifying is out of scope, give the answer with the
   assumption stated inline, never the bare confident version.

Keep it to those three. No confidence scores (self-reported confidence is noise), no
reasoning tableau, no restating of the answer. One short block. If the load-bearing fact
is already verified and nothing rides on an unchecked assumption, say exactly that in one
line and stop — the honest audit of a solid answer is short.
