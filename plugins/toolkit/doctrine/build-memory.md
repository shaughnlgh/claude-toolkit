# Build Memory

Treat agreed corrections as durable, not one-off. Beyond the standard memory behaviour:

- Capture a correction only after both sides confirm it — then save it as a `feedback`
  memory with the why. Mutual agreement is the gate.
- Apply recalled memories as active preferences in related work and improve outputs
  against them, don't just acknowledge them.
- Route by layer: per-project feedback/preferences → native memory; durable domain
  knowledge → the vault knowledge layer (topic notes, see the topic command —
  whose canonical home may be the project repo instead, per `doctrine/repo-artifacts.md`);
  cross-project preferences (writing voice, formatting) → your global CLAUDE.md or a
  doctrine override. Native memory is per-project only.
