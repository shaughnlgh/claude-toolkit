Plan, approve, build, review, ship.

claude-toolkit is a Claude Code plugin that runs a plan-first workflow.

Install View the repository

Installshell
claude plugin marketplace add https://github.com/shaughnlgh/claude-toolkit.git
claude plugin install toolkit@shaughn-toolkit

Overview

What it is

A brief becomes a plan note that you approve, worker agents build it step by step, a review panel checks the result, and a ship flow opens and merges the pull request under the git permissions the plan note records.

The plugin ships 14 worker agents, 20 skills, 8 slash commands, 13 hooks, 4 workflows, write-time rules and the doctrine that ties them together. The main conversation plans and supervises. Worker agents make every file change and report back. Plan notes and topic notes go into a vault, which is any folder of markdown on your machine. No note-taking app is required.

  • 14 worker agents → Make every file change and report back.
  • 20 skills → Including crawl and plan-guide.
  • 8 slash commands → Including /toolkit:setup and /toolkit:topic.
  • 13 hooks → Switched on in every session at install.
  • 4 workflows → Including plan-builder, execute-runner and ship-runner.
  • Write-time rules Injected at session start and into every worker agent at spawn.
  • Doctrine Ties the agents, skills, commands, hooks and workflows together.

Audience

Who it is for

Any Claude Code user who wants planned, reviewed changes instead of one long unplanned session. The toolkit suits work that touches a real repo, where you want a written plan to approve before anything changes, a review before anything ships, and a record of what was decided.

Hooks

What switches on at install

Installing the plugin switches on thirteen hooks in every Claude Code session, with no opt-in and no separate config. Read docs/hooks.md before you trust the toolkit with a repo. It lists what each hook blocks, what it only asks, and every environment variable it honors.

protect-files.sh
Blocks a write to keys, certificates, lockfiles, generated files, .git/, secrets/ and hook scripts, and asks before a write to .env* and .claude/settings*.json.
scan-secrets.sh
Asks for confirmation when written content looks like a credential. It never blocks.
block-dangerous-commands.sh
Blocks a fixed list of destructive shell command patterns.
session-start.sh
Injects the write-time rules, a doctrine pointer, a git briefing and the current repo's vault topics at session start and after a compaction.
subagent-rules.sh
Injects the same write-time rules and doctrine pointer into every worker agent at spawn.
notify.sh
Fires a native OS notification when Claude needs input.
md-wrap-check.sh
Flags hard-wrapped prose in a markdown write. It warns and never blocks.
context-sentinel.sh
Nudges the conversation to delegate and plan a handoff past 200k, 400k and 600k tokens of context. It never blocks.
conductor-guard.sh
Refuses a direct edit to a project file by the main conversation, so that a worker agent makes it. TOOLKIT_CONDUCTOR_EDITS=1 is the only override.
design-rules-reminder.sh
Points at the design rules catalog once per session when a frontend file is edited.
agent-model.sh
Adds the resolved model and effort to an agent call that does not carry them.
worker-spawn-mode.sh
Records the session's permission mode when it starts a worker session, so the worker session runs in the same mode. It prints nothing and never changes the call.
remember-guard.sh
Warns when a reply suggests a commit but the plan note has no remember line. It never blocks.

Overrides

Make it yours

The doctrine, rules, agents and skills are defaults, not law. When your own config disagrees, yours wins, so you bend the toolkit to how you and your team work instead of forking it.

Put a same-named copy under your global ~/.claude/, or let /toolkit:override make the copy for you, then edit it. Most specific wins: project config beats your global config, which beats the plugin's defaults. The session-start hook announces every active override, so a change is never silent. The safety sections may be tightened, never loosened.

Claude Code
/toolkit:override conventions
/toolkit:override rules security
/toolkit:override code-reviewer

Get started

Install

  1. Add the marketplace and install the plugin.

    claude plugin marketplace add https://github.com/shaughnlgh/claude-toolkit.git
claude plugin install toolkit@shaughn-toolkit

  2. Then start a new Claude Code session and run /toolkit:setup. It checks the CLI prerequisites (gh, glab, jira-cli, jq and python3), creates the vault config, and prints a readiness report. docs/prerequisites.md gives the install and auth command for each CLI.

Supported platforms

  • macOS: supported and tested.
  • Linux: untested.
  • Windows: through WSL, untested.
