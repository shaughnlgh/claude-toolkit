claude-toolkit

A Claude Code plugin that runs a plan-first workflow. A brief becomes a plan note that you approve, worker agents build it step by step, a review panel checks the result, and a ship flow opens and merges the pull request under the git permissions the plan note records.

What it is

The plugin ships 14 worker agents, 20 skills, 8 slash commands, 12 hooks, 4 workflows, write-time rules and the doctrine that ties them together. The main conversation plans and supervises. Worker agents make every file change and report back. Plan notes and topic notes go into a vault, which is any folder of markdown on your machine. No note-taking app is required.

Who it is for

Any Claude Code user who wants planned, reviewed changes instead of one long unplanned session. The toolkit suits work that touches a real repo, where you want a written plan to approve before anything changes, a review before anything ships, and a record of what was decided.

What switches on at install

Installing the plugin switches on twelve hooks in every Claude Code session, with no opt-in and no separate config. Read docs/hooks.md before you trust the toolkit with a repo. It lists what each hook blocks, what it only asks, and every environment variable it honors.

protect-files.sh
Blocks a write to keys, certificates, lockfiles, generated files, .git/, secrets/ and hook scripts, and asks before a write to .env* and .claude/settings*.json.
scan-secrets.sh
Asks for confirmation when written content looks like a credential. It never blocks.
block-dangerous-commands.sh
Blocks a fixed list of destructive shell command patterns.
session-start.sh
Injects the write-time rules, a doctrine pointer, a git briefing and the current repo's vault topics at session start and after a compaction.
subagent-rules.sh
Injects the same write-time rules and doctrine pointer into every worker agent at spawn.
notify.sh
Fires a native OS notification when Claude needs input.
md-wrap-check.sh
Flags hard-wrapped prose in a markdown write. It warns and never blocks.
context-sentinel.sh
Nudges the conversation to delegate and plan a handoff past 200k, 400k and 600k tokens of context. It never blocks.
conductor-guard.sh
Refuses a direct edit to a project file by the main conversation, so that a worker agent makes it. TOOLKIT_CONDUCTOR_EDITS=1 is the only override.
design-rules-reminder.sh
Points at the design rules catalog once per session when a frontend file is edited.
agent-model.sh
Adds the resolved model and effort to an agent call that does not carry them.
remember-guard.sh
Warns when a reply suggests a commit but the plan note has no remember line. It never blocks.

Install

claude plugin marketplace add https://github.com/shaughnlgh/claude-toolkit.git
claude plugin install toolkit@shaughn-toolkit

Then start a new Claude Code session and run /setup. It checks the CLI prerequisites (gh, glab, jira-cli, jq and python3), creates the vault config, and prints a readiness report. docs/prerequisites.md gives the install and auth command for each CLI.

Supported platforms

  • macOS: supported and tested.
  • Linux: untested.
  • Windows: through WSL.

The three flows

The walkthroughs follow one invented project, todo-api, with a vault at ~/notes.

  • Plan flow: a brief becomes a validated plan note that waits for your approval.
  • Execute flow: worker agents build the approved plan, run its Validation Steps and a review panel, and stop with a commit suggestion.
  • Ship flow: the reviewed slice is committed, pushed, opened as a pull request and merged, up to the ceiling the plan note records.
  • Parent and child sessions: how one session plans and another builds.
