Execute flow walkthrough

The execute flow builds an approved plan note end to end and stops with a commit suggestion. It asks nothing after the run options, and it never runs the suggested git commands.

The setup

The project is still todo-api, and the plan note from the plan flow walkthrough sits in ~/notes with status: approved.

The steps

  1. run the execute flow here, or yes to the run-here form of the post-approval question.

    The flow reads the run options from the plan note and asks nothing more. It checks the seat, which is the repo's main checkout. It opens a worktree for the plan with no question when another session holds the main checkout, when the main checkout holds changes, or when it sits on its default branch, and it runs the repo's install step inside that worktree. It checks the tree and the branch and runs topic recall.

  2. nothing.

    The flow moves the plan note to status: in-progress, tells you the step count and the first line of each Implementation Step, and says that a permission prompt pauses the run until you answer it. It then launches the execute-runner workflow.

  3. an answer to any permission prompt the run raises.

    The runner checks a baseline, then runs one implementer agent per Implementation Step, in plan order. A verifier runs the plan's Validation Steps, with one fix round for a failing step. The runner captures the diff and hands it to the review-mr panel, whose verifier must reproduce a finding before it counts. A bounded fix loop fixes the reproduced findings. A cold reader then reads the final diff with no context. When nothing blocked, a doc pass updates the repo docs the change touched, the Validation Steps run again when a fix or the doc pass changed files, and a remember pass proposes topic note updates.

  4. nothing yet. Read the report.

    On a clean run the report opens with the Repo, Branch and Scope lines, then a line that begins Suggested commit, then the Remember: line and each file to stage, with a paste-ready block that names every path. A list under the line "To settle" holds the manual checks and open items, or "none". The plan note records the session as execute-flow finished:, which the ship flow reads.

    A Validation Step that needs the running local stack cannot run in a worktree. The report then begins with the line "Deferred to the seat" and one line per such step, and those steps run later in the seat run from the main checkout.

    On a blocked run the report opens with every blocked reason instead, says what you settle, and offers no commit.
