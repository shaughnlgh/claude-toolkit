Hooks

Hooks are scripts that Claude Code runs on session events. Installing the plugin switches on all 12 in every session, with no opt-in and no separate config. Most add context or ask you to confirm. A few hard-block. Read this page, or docs/hooks.md for the full accounting, before you trust the toolkit with a repo.

Across all 12

Two properties

Fails safe. No hook can crash or hang your session. protect-files.sh and block-dangerous-commands.sh need jq to parse the tool call, so without it they block that one write or command rather than let a check that cannot run pass. The other hooks fall back to less output, or do nothing, when they cannot run.

Reads no network, with one exception: the verbose mode of session-start.sh (TOOLKIT_SESSION_VERBOSE=1) calls gh pr view when the gh CLI is installed. Every other path is local: file reads, git plumbing, jq and OS notification APIs.

6 hooks

PreToolUse

Runs before a tool call, on the tools its matcher names, and can block, ask or add context.

protect-files.shBlocks Asks

Hard-blocks a write to key and certificate files, credentials.json, .npmrc, .pypirc, lockfiles, generated or minified files, anything under .git/ or secrets/, and hook scripts. Asks before a write to .env files, .claude/settings.json and .claude/settings.local.json.

MatcherEdit|Write

scan-secrets.shAsks

Scans the content being written for secret-shaped strings: access keys, host tokens, sk- style keys, chat tokens, private-key blocks, connection strings with a user and password, and credential names assigned a quoted value. Every match asks for confirmation, because a match could be a test fixture. It never blocks.

MatcherEdit|Write

block-dangerous-commands.shBlocks

Hard-blocks common destructive command patterns: a push to a protected branch and any force push (--force-with-lease is allowed), a recursive forced rm on /, ~, . or a system directory, DROP, TRUNCATE and an unbounded DELETE FROM through a database client, a world-writable chmod, curl or wget piped to a shell, writes to raw devices, mkfs and dd to a device, git reset --hard, git clean -f, and package publish commands without a dry-run flag. It has no ask path.

MatcherBash

SettingCLAUDE_PROTECTED_BRANCHES replaces the default protected list, main,master plus the repo's configured default branch.

conductor-guard.shBlocks

Denies a direct edit to a project file by the main conversation, with a reason that routes the edit to a worker agent. Worker edits pass, and so do conductor writes outside the project and paths under ~/.claude/ or the vault. It is a workflow guard, not a security boundary.

MatcherEdit|Write|NotebookEdit

SettingTOOLKIT_CONDUCTOR_EDITS=1 is the only override: in the shell for one session, or for one project through /setup check 10.

design-rules-reminder.shAdds context

When the target file matches a frontend pattern, by extension or directory, adds a one-line pointer at the rules/design.md catalog to the model's context, once per session. It never blocks.

MatcherEdit|Write|NotebookEdit

agent-model.shAdds context

Adds the model and effort that scripts/resolve-models.sh resolves for an agent to an Agent call that does not carry them. A field the call already carries wins. A bare name that one of your own agents shadows gets nothing added. It never blocks or asks.

MatcherAgent

SettingTOOLKIT_MODELS_FILE points at a models file in place of ~/.claude/toolkit-models.json.

2 hooks

PostToolUse

Runs after a tool call and feeds a finding back. Neither hook here blocks.

md-wrap-check.shWarns

Flags hard-wrapped prose in the content a .md write just produced and feeds the finding back to the model. It checks only the new content.

MatcherEdit|Write

context-sentinel.shWarns

Reads the session transcript for the context size. Past 200k tokens it nudges the model to delegate and plan a wrap-up, past 400k it also tells you to reach a stable point and continue in a fresh session, and past 600k it says to wrap up now. Each threshold fires once per crossing.

MatcherEvery tool

SettingTOOLKIT_CTX_SENTINEL=0 turns the hook off.

1 hook

SessionStart

Runs when a session starts, resumes, clears or compacts.

session-start.shAdds context

Injects the eight write-time rules, using your override where one exists, a doctrine pointer, a git briefing, the current repo's vault topics, and a line when another live session shares the main checkout. It announces every active override. On startup it also prints a one-line status for you. After a compaction it injects the rules again with the session's compact handoff, and from the second compaction on it warns.

Matcherstartup|resume|clear|compact

SettingTOOLKIT_SESSION_VERBOSE=1 extends the git briefing, and adds the current PR through gh pr view when gh is installed.

1 hook

SubagentStart

Runs once for each worker agent, before it does anything else.

subagent-rules.shAdds context

Injects the same eight rule bodies, a pointer to the doctrine index, and the frontend and design pointer into every worker at spawn, and announces any active rule overrides. It is the worker-side counterpart to session-start.sh.

MatcherNone

1 hook

Notification

Runs on every notification Claude Code raises.

notify.shNotifies

Fires a native OS notification with a fixed title and message when Claude needs input: osascript on macOS, notify-send on Linux, a PowerShell toast on WSL. It never reads the message from the hook payload, because that input is untrusted.

MatcherNone

1 hook

Stop

Runs each time Claude finishes a reply.

remember-guard.shWarns

Warns you, once per session, when a reply suggests a commit but the session's in-progress plan note has no Remember: line under Plan Changes During Execution. It never blocks.

MatcherNone

SettingTOOLKIT_REMEMBER_GUARD=0 turns the hook off.

Boundaries

What enforces what

  1. The permission system Claude Code's own permission prompts govern every tool call, including every Bash command. That is the outer boundary.

  2. Matcher-scoped hard blocks protect-files.sh within Edit|Write, and block-dangerous-commands.sh for its listed patterns within Bash. Inside those scopes the deny is absolute.

  3. Advisory warnings scan-secrets.sh only ever asks.

A file written by a subprocess started through Bash does not pass through protect-files.sh, unless the permission system stops the call or the command matches a blocked pattern. These hooks guard against common mistakes. They are not a sandbox.
