Skills

The toolkit ships 20 skills: instructions Claude loads at the moment they apply. A skill whose name ends in -flow runs the work for you. A skill whose name ends in -guide is the manual a session follows by hand. You ask for some by name, and others fire on their own inside the plan-then-build pipeline.

3 skills

Flows

Each flow runs one stage end to end and fires only when you ask for it by name. The walkthroughs follow all three on an invented project.

plan-flow

One run from brief to plan note. It reads the run options, runs topic recall and a route check, launches the plan-builder workflow for discovery, runs the planning grill on that evidence, then has the planner draft the plan, the plan-critic run a pre-mortem with a revise loop, and a cold red team read it. It writes and validates the plan note, prints its plain language summary and asks for your approval. It never writes repo files and never runs a git command that changes state.

TriggerYou ask for the plan flow by name, with a brief or on a scaffolded plan note. From crawl, only when you reply yes or run the plan flow to its offer.

Run the plan flow on this: add CSV export to the reports page.

execute-flow

One run that builds an approved plan note end to end. It reads the run options and then asks nothing, opens a worktree when another session holds the main checkout, the checkout holds changes or it sits on its default branch, and runs the execute-runner workflow. When nothing blocked, it closes with a commit suggestion that you run yourself. Steps that need the running local stack wait for a seat run from the main checkout.

TriggerYou ask for the execute flow by name on an approved plan note, or reply run the execute flow here, or yes to the run-here question.

Run the execute flow on the add-csv-export plan.

ship-flow

One run that commits, pushes, opens the MR or PR, watches the pipeline, waits in the background on a slow pipeline or a pending bot review, works the bot review threads, merges, tags and cleans up a slice the execute flow reviewed. It stops at the ceiling the plan note records and asks no question.

TriggerYou ask for the ship flow by name after an execute-flow report, or a worker session's first prompt names it, or that worker session's lead sends <planName>: run the ship flow. Never from crawl.

Run the ship flow on the add-csv-export plan.

6 skills

Planning

From a new brief or ticket to an approved plan, or a tree of plans for a large effort.

crawl

The front door for new work. It takes a brief or a ticket, checks it against the codebase, and recommends a route: wayfinder, plan-guide, or no plan. On a route that writes a plan or plan stubs, you confirm the route first. A trivial no-plan route states the route in one sentence and goes ahead. On the plan-guide route it scaffolds the plan note and ends with an offer to run the plan flow on it.

TriggerA session opens with a new piece of work and no plan note exists for it yet.

Here's the ticket: <link>. We need bulk order editing in the admin.

plan-guide

Writes a plan note to your vault and stops for approval before any implementation. It is the single source of truth for the plan note's layout, naming, frontmatter and status lifecycle, and its planning runs the planning grill once, after discovery. After approval it asks whether to start a worker session for the execute flow, run the execute flow here, or stop.

TriggerCreating, filling in or closing out a plan note, or starting a planning session.

Let's plan adding rate limiting to the login endpoint.

grill

A requirements interview before a plan exists: one question at a time with a recommended answer, answering what it can from the code, then a glossary written to docs/glossary.md and decision records to docs/decisions/. When a crawl or a planning flow loads it, it writes nothing, takes only your own answer, and hands the answers back.

TriggerYou ask to grill, elicit or interview requirements, crawl's grill check loads it on a wayfinder route you confirmed, or a planning flow loads it as its planning grill.

Grill me on the new notifications feature before we plan it.

wayfinder

Turns a large, fuzzy investigation or migration into a mapped set of tickets. It agrees the outcome and what success means with you first, then writes an issue register, a parent umbrella plan, and one child plan stub per task, each grilled by its own planning.

TriggerYou ask to map, scope or break down a big multi-part effort before planning it, or crawl or the plan flow's route check sends the work here with your confirmation.

Map out migrating the legacy monolith to a modular service before we plan each piece.

expedition

The ticket-to-complete pipeline for big, deliberately committed work. It sequences crawl, grill, the split decision, planning, execution and review through recommend-and-confirm gates, and keeps its stage in a vault work note so the effort survives across days. Completion is always your word, never inferred.

TriggerOnly when you invoke it, or ask to resume one. Never automatic.

Run the expedition on this: <ticket link or brief>.

jira

A ticket-to-brief adapter. It fetches an issue through jira-cli and returns a verbatim brief, with metadata, the full description, comments and issue links, for crawl or expedition to plan from. It creates a ticket only on your yes to a draft it showed, and never edits, transitions or comments on one.

TriggerCrawl's ingest step meets a ticket key or ticket URL, you ask to fetch one directly, or the ticket question's create answer reaches your yes on a draft.

4 skills

Building and testing

What a session follows while it writes the code.

execution-guide

Execution mechanics after a plan is approved: topic recall at the start, delegation to worker agents, progress reports in a fixed format, the doc update pass, and debugging with runtime evidence.

TriggerStarting execution of an approved plan, or debugging a runtime or integration issue.

The plan is approved, go ahead and implement it.

testing-gate

Reads the tests option from the plan note or the session cache, and asks once, up front, only when neither has it.

TriggerStarting a feature, bugfix or refactor, after crawl has routed when both match.

Add a CSV export to the reports page.

test-first

The red-green-refactor loop that runs once testing-gate has said tests are required. It chains from the gate and never decides the gate itself.

TriggerWriting code on a task where tests were required. It needs no separate prompt.

resolving-merge-conflicts

Shows an overview and a side-by-side view of every conflict, resolves each hunk by intent, and waits for your confirmation before writing.

TriggerYou ask for help with a git merge or rebase conflict.

Help me resolve these merge conflicts.

5 skills

Review and investigation

Adversarial checks on a diff, a plan or a merge request, and root-cause work on an incident.

red-team

Gates the end of an implementation slice. It recommends an adversarial review and, on your confirmation, runs the review-mr reviewer and verifier panel over the uncommitted diff. It delegates one fix round for the confirmed findings, records each finding's outcome, runs the doc pass and the remember pass once each, and closes with a commit suggestion.

TriggerA closure signal arrives while uncommitted implementation changes exist, or you ask to red team code or a diff.

I'm happy with this, let's continue.

inversion

A pre-mortem for a plan, decision or code fix: up to seven ranked failure causes, a verdict that names the fatal flaw when one exists, a rebuilt plan with walk-away checks, the adversary's view, and one measurable tripwire per failure mode. It never reassures.

TriggerYou invoke it by name, or ask whether a plan or fix is good, looks right or is ready to ship.

Is this a good plan? Invert it before we go ahead.

gitlab-mr-review

A multi-dimension merge request review. It fans out the reviewer agents plus MR-specific dimensions, each finding carrying a tag, a self-score and a file:line citation, checks each dimension's findings with one batched verifier against the local checkout, and reports the confirmed findings with a final score.

TriggerYou ask to review a merge request on a host that glab serves.

review-threads

Works the reviewer threads on a pushed MR or PR, from bots and from people. It lists the open threads, fixes or pushes back on each, reports the state, and recommends a merge only when every thread is resolved and the pipeline is green. It uses glab or gh.

TriggerYou ask to go through or address the review comments on an MR or PR.

incident-investigate

Root-cause investigation for a production incident. It fences scope to the question and items you named, checks that the project's evidence sources are reachable, gathers evidence in parallel with a citation per finding, reaches one verdict, and writes a technical incident note and a stakeholder summary. It never implements a fix and never changes production.

TriggerYou ask to investigate an incident, or paste a production alert with "find the cause".

Investigate this incident: orders 1001, 1002, and 1003 were captured twice. Find the cause.

2 skills

Handoff and compaction

Keeping the state of a session when it ends or compacts.

handoff

Compresses the session into a continuation note in the vault, so another person or a later session can pick the work up cold.

TriggerYou ask to hand off or to write a continuation note.

Write a handoff note for this session.

pre-compact

Readies a session for compaction. It checks that the plan or work note, every promised note, uncommitted changes and running background tasks are recorded, finishes what is not, and writes a state-only handoff under 3,000 bytes that the session-start hook injects once after the compaction. It never commits and never compacts the session itself.

TriggerYou ask whether it is safe to compact, ask to prepare for a compaction, or say pre-compact. A request to hand off goes to handoff instead.

Is it safe to compact?

Make it yours

Replacing a skill

Run /toolkit:override <name> with a skill name to copy a skill's whole directory to ~/.claude/skills/<name>/, then edit your copy. Claude Code resolves your copy for the bare name. Overrides covers the details.
