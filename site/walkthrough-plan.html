Plan flow walkthrough

The plan flow turns a brief into a validated plan note in your vault and stops for your approval. It writes no repo file and runs no git.

The setup

The project is an invented repo named todo-api. The vault is the folder ~/notes. /setup has created ~/.claude/toolkit-vault.json from the shipped template, with vault_path set to that folder. The brief is: add a due date to each todo and a filter that lists the overdue ones.

The steps

  1. the brief, in a Claude Code session started in todo-api.

    The crawl skill reads the brief, checks it against the codebase, and recommends a route. For one piece of work on one branch the route is plan-guide. Once you confirm it, crawl asks the run options in at most two question forms, the first of which opens with the question below, and it asks whether the work has a ticket.

    Where does the ship flow stop?

  2. an answer to each question form.

    Crawl creates the plan folder under ~/notes, writes the brief beside the plan note, and scaffolds the note with its evidence in Current Context, Assumptions and Open Questions. It ends the reply with the plan flow offer.

    The plan note is scaffolded. Run the plan flow on it now?

  3. run the plan flow, or yes.

    The plan flow reads the run options from the note, runs topic recall over the vault topic notes and the repo's docs/, and states the route in one sentence. The crawl's evidence is the discovery, so the flow launches nothing yet. It then runs the planning grill. It prints one line that starts Outcome: and states the outcome of the work as the grill understands it, then asks one question at a time.

  4. your own answer to each grill question.

    The flow writes the agreed points into Current Context under the line Agreed in the grill:. It launches the plan-builder workflow, which drafts every plan section, runs a pre-mortem with a revise loop, and has a second critic read the plan cold. The flow writes the note into the vault, runs validate-plan.py on it, and sets status: review.

  5. nothing yet. Read the report.

    The flow states the final verdict, the cold verdict, and every blocked reason and gap, or "none". It prints the note's Plain Language Summary under the heading Plain language summary and asks for your approval.

    Approve this plan as written, or tell me what to change?

  6. your approval, or what to change.

    On approval the flow sets status: approved and today's date, validates the note again, and ends with the post-approval question. In a session that is not a crawl parent it takes the run-here form.

    The plan is approved. Run the execute flow here now?

    A session whose name starts parent- gets the child form instead, which recommends a child session. Parent and child sessions shows that shape.
