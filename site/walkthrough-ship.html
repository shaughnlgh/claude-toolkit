Ship flow walkthrough

The ship flow carries a reviewed slice up the ladder suggest, commit, push, mr, merge, release, and stops at the ceiling the plan note records. It prints every external side effect before it starts and asks nothing.

The setup

The project is still todo-api. The execute flow finished on the plan note in ~/notes, and the note records ceiling: merge. The ceiling is the limit on what any flow may do in git:

  • none stops at suggest: the flow hands you the commit commands and runs none.
  • mr commits, pushes, opens the pull request, watches the pipeline and works the bot review threads.
  • merge adds the merge, and with tag_merge: true it also tags the merge commit.

The steps

  1. run the ship flow.

    The flow reads the run options from the plan note. One verifier reads the host, the remote, the branch, the tree and any open pull request, and the flow derives where the run starts from that observed state, never from your input. It takes the staging list and the commit message from the execute flow's report or from the shipping record on the plan note.

  2. nothing. Read the preview.

    The flow states the ceiling, in the form "The ceiling is <ceiling>, so the run stops at <stage>." It prints the commit message, the pull request title and body, each path to stage, the fix message templates fix(ci): <failing check> (ship-flow) and fix(review): <thread summary> (ship-flow), the reply template Fixed in <short sha>: <what changed>, the protected paths, and that no commit carries a Co-Authored-By trailer and that human threads are never touched.

  3. nothing.

    The flow launches the ship-runner workflow. Its agents stage each listed path by name and commit, push the branch, and open the pull request with gh pr create, or the merge request with glab mr create. A verifier watches the pipeline of the pushed commit, and a failing check gets a bounded fix loop. The runner waits for a bot review, then fixes, replies to and resolves each fixable bot thread, in up to three rounds. It merges only that exact commit, on a green pipeline with no open thread, and then removes the branch and the worktree when no other session sits in them. When a pipeline or a bot review is slow, the flow waits in the background with watch-mr.sh and relaunches itself.

  4. nothing yet. Read the report.

    The report opens with the Repo, Branch and Scope lines, then MR: <url> followed by merged <sha>. Under Fixed beyond the plan: it lists each fix commit with its reason, and under Caveats: it lists what is left for you, such as a human review thread. After a merge it gives the undo command, git revert -m 1 <mergeSha> for a merge commit. The plan note records the session as ship-flow finished: merge.

Other ceilings

Under ceiling: none the report is a commit handoff: the three header lines, a line that begins Suggested commit, and a paste-ready block that names each path. Under ceiling: mr the run stops once the pull request is open, its pipeline watched and its bot threads worked. Raise the note's ceiling to merge and ask again to merge it.

When the execute flow deferred a Validation Step to the seat, the run stops at mr until the seat run passes on the commit it would merge.
